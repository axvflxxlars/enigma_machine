# Enigma M3 і брейкер на C

Симулятор Enigma M3 і програма, яка зламує англійський шифротекст без кріпу, тобто без відомого фрагмента відкритого тексту. Злам іде через індекс збігу (IoC) і n-грами (метод Gillogly / Weierud–Sullivan).

Дедлайн: **25 листопада**.

## Збірка і запуск

```bash
make            # ./enigma і build/gen_testcase
make test       # усі тести
make clean && make debug   # з -g і AddressSanitizer
```

```bash
echo "HELLO WORLD" | ./enigma encrypt --key "I-II-III B AAA AAA AB CD EF"
./enigma crack --ngrams data -v < tests/testset/t01.cipher.txt
```

Формат ключа: `ротори рефлектор ринги позиції [пари плагборду]`, наприклад `IV-II-V C KTR QWE AB CD EF`.

## Симулятор

Модель Enigma M3, машини німецького військово-морського флоту. Підтримуються три ротори з п'яти (I–V; морські ротори VI–VIII не реалізовано), рефлектор UKW-B або UKW-C, ринги (Ringstellung), стартові позиції (Grundstellung) і плагборд (Steckerbrett) до 13 пар.

### Як проходить одна літера

На кожне натискання клавіші спершу крокують ротори, потім літера проходить шлях:

```
клавіша → плагборд → правий → середній → лівий → рефлектор
                                                     ↓
лампа   ← плагборд ← правий ← середній ← лівий ←─────┘
```

- **Ротор** — фіксована перестановка 26 літер. Поворот ротора на позицію `p` з рингом `r` зсуває її на `p − r`: літеру зсунуто на вході й повернуто на виході.
- **Рефлектор** з'єднує літери попарно, тож шлях повертається тими самими роторами у зворотному напрямку. Звідси дві властивості Енігми: шифрування й розшифрування — це одна операція, і жодна літера не шифрується сама в себе.
- **Плагборд** міняє місцями пари літер до і після роторів.

### Крок роторів і double-step

Правий ротор крокує завжди. Коли ротор стоїть на своєму нотчі, наступне натискання штовхає сусіда зліва:

| Ротор | I | II | III | IV | V |
|---|---|---|---|---|---|
| Нотч | Q | E | V | J | Z |

Особливість M3, **double-step**: середній ротор, що стоїть на своєму нотчі, крокує сам і штовхає лівий. Тому він робить два кроки поспіль: `ADU → ADV → AEW → BFX` для I-II-III. Якщо середній і правий одночасно на нотчах (`AEV`), середній крокує лише раз: `AEV → BFW`.

Реалізація: `enigma_step()` у `src/enigma.c`.

### Приклад

```bash
echo "HELLO WORLD" | ./enigma encrypt --key "I-II-III B AAA AAA"
# ILBDAAMTAZ
echo "ILBDAAMTAZ" | ./enigma encrypt --key "I-II-III B AAA AAA"
# HELLOWORLD
```

Усе, крім латинських літер, відкидається, малі літери стають великими.

### Інтерфейс (`src/enigma.h`)

| Функція | Що робить |
|---|---|
| `key_init` | ключ за замовчуванням: I-II-III, UKW-B, AAA, AAA, без плагборду |
| `key_parse`, `key_print` | читання і друк ключа у форматі `IV-II-V C KTR QWE AB CD` |
| `enigma_crypt` | зашифрувати/розшифрувати `len` літер, ключ не змінюється |
| `enigma_step` | один крок роторів, винесено окремо для тестів |
| `enigma_build_path` | таблиця шляху `path[i][c]` для брейкера: ротори з рефлектором без плагборду |
| `enigma_crypt_path` | розшифрування за таблицею з даним плагбордом: `plug[path[i][plug[c]]]` |

### Швидкість

Брейкер викликає машину мільйони разів, тому її прискорено. Заміри: 300 літер, `-O2`, AMD Ryzen 7 7700, WSL.

| Що | Час на 300 літер |
|---|---|
| `enigma_crypt`, перша версія | 6.0 мкс |
| `enigma_crypt`, без ділення `%` у гарячому циклі | **2.6 мкс** |
| `enigma_crypt_path`, одна спроба плагборду | **0.18 мкс** |
| `enigma_build_path`, один раз на кандидата | ~60 мкс |

Таблиця шляху працює тому, що під час підбору плагборду ротори, ринги й позиції не змінюються. Перестановку роторів для кожної позиції достатньо порахувати один раз, після чого кожна спроба плагборду — це три звернення до масивів на літеру.

### Тести (`tests/test_enigma.c`, 50 перевірок)

- **Еталонні вектори:** `AAAAA → BDZGO` (I-II-III B AAA AAA), `AAAAA → EWTYX` (ринги BBB).
- **Крок роторів:** double-step `ADU → BFX`, одночасні нотчі `AEV → BFW`, нотчі всіх п'яти роторів у правій і середній позиції, перехід `Z → A`.
- **Властивості:** розшифрування з тим самим ключем повертає відкритий текст (з рингами, UKW-C і 10 парами), жодна літера не шифрується в себе.
- **Таблиця шляху:** на 4 ключах по 400 літер `enigma_crypt_path` дає те саме, що `enigma_crypt`.
- **`key_parse`/`key_print`:** друк повертає той самий рядок, некоректні ключі відкидаються (однакові ротори, повтор літери в плагборді, зайвий текст, неіснуючий ротор чи рефлектор, задовгий рядок).
